## 1 · 共识与整体创意

### 本次决定与覆盖关系

用户已经看过 3D 预览，明确认为人物、小狗和转场效果不满意。本版以这次反馈为准，覆盖旧 V3 的相关制作要求；V3 原文可从仓库Git历史查看，重复归档拟清理；本轮删除被自动审批拦截，尚未移除。

**已明确的方向：**

- 去掉《爱乐之城》主题，以及围绕钢琴、白衬衫黄裙和双人舞的强制制作任务。停止补做人物 3D、服装碰撞、手指触键、牵手和脚底接触。
- 小狗改为**精绘 2D 动画**；问题首先在造型，不能只给旧模型增加摇尾和眨眼。
- 保留哈利波特的魔法感，加入 **1994《狮子王》与 2002《小马王》原版动画**方向，优先查找原版画面，不再拿低质自制角色充当原版。
- 用户说的“沙图”已确认是**沙画：粒子聚散、沙粒勾勒人物与城市**。沙画用于人生旅程与有叙事关系的转场，同时比较其他形式；不因旧四章编号限制新结构，也不锁定整片只能沙画。
- 她的人生路线已确认：**河南 → 天津 → 北京·中国政法大学 → 香港·香港科技大学 → 深圳**。
- 用户本人的路线已确认：**武汉 → 南京·东南大学 → 上海·上海交通大学 → 深圳**。两条路线分开叙述，在深圳汇合，不替换、不混写。
- 用户明确要求：**照片有专门一章；《狮子王》和《小马王》共同有一章；结尾有精美蛋糕。**五章数量与顺序已经用户确认，具体镜头和时长仍是制作建议。
- 全片转场重新设计，不能只换一套通用遮幕。
- 用户已确认星铁参考为《如我所书》，并进一步明确：**书仍然必须是哈利波特的感觉**。外观走古旧装帧、羊皮纸、烫金、封蜡和烛光；不采用星铁星盘封面或科幻UI。
- 浪漫以“童话般的惊喜”为主调：每次触摸都有世界的回应，个人旅程和书信让奇遇有专属感。
- 可以直接使用、下载安装必要的免费制作工具和免费可用素材，无需为普通安装再次询问；不因此购买订阅、素材或云服务。
- 验证保持适量：不做过多测试，不反复计算SHA或反复核对同一提交。没有变更的资源复用已有记录；先用代表样镜判断美术。
- 蛋糕已确定为**深蓝与金色的魔法星空风**；书温柔、小狗调皮的性格分工已确认。
- 照片章放**4–5张**，后续预览先用网图占位；书信和署名保留，可暂拟文字看效果。
- 最终必须能在**GitHub Pages**展示；当前仅写计划，不能把本地预览或独立R2素材链接当成交付网站。
- 文件保持精简：一个总体计划入口，删除被合并的草稿和临时检查产物；保留源码、制作母版与必要恢复资料。

**已选定的外观与主调：**哈利波特式魔法古书，童话般的惊喜。可探索地图、沙画长卷、纸剧场、星图、照片显影等作为辅助表达或比较方案，见本文「沙画之外的创意形式」部分。下面的具体镜头组合仍是制作建议，不能记为用户已逐镜批准。

### 已选定的创作主线：一本只认识她的魔法书

保留作品名《写给师宝宝的一场梦》，候选副标题为“沿途有光，往后同路”。

**2026-10-03 用户已选择①“一本只认识她的魔法书”。**书认出“师宝宝”后，她的五站旅程逐页苏醒；随后展开你的四站路线，在深圳第一次并行。照片、完整书信、两部原版动画与精美蛋糕都有明确篇幅。列车与秘密图书馆不再作为整片并行方案，仅保留为可选灵感，不自动加入。

用一本会显影的魔法古书承载真实路线。外观与氛围以哈利波特式书房、古旧装帧、羊皮纸和烛光为主；《如我所书》只提供“经历被写入、可以回看”的结构参考。书中的地图进入沙画，城市之间用形态变化连接；《小马王》的远行意象与《狮子王》的星空、勇气和归属意象，作为故事里的电影回声。网页保留触摸、停留、阅读和回应。

她的成长是叙事中心。“在深圳遇见我”是你们故事的新一章，不把她此前的努力解释成仅仅为了遇见伴侣。电影情节是寓意，不是她的人生事实。

## 2 · 确认台账与真实内容

### 怎样理解“确认过”

每个细节都要有状态与依据。不能把写进文档等同于用户已经选择、素材已经拿到或画面已经验证。本文使用五类标记：

- **U · 用户明确**：来自本次对话，可直接执行。
- **F · 已核实事实**：有本地代码/文件或明确来源支撑。
- **P · 制作建议**：由本方案提出，可先用于样镜；未被用户逐项选择，参数没有实测。
- **M · 待素材/资料**：还缺准确图片、原片、参考帧或个人事实。
- **V · 待样镜验证**：必须实际制作后判断，不能靠文档关闭。

#### 沙画自身也有三种不同做法

1. **纯沙画光台**：暖光透过深浅沙层，一幅画连续变成另一幅；绘画性最强，对底稿要求最高。
2. **沙画与原版画面相接**：沙粒揭开保留原有色彩的电影/照片窗口，再由边缘散回沙画；兼顾原版辨识度与个人旅程。
3. **彩色记忆画面＋局部沙粒**：主画面以精绘/照片为主，只用沙粒表达移动、时间与转场；更鲜明，但沙画存在感较弱。

用户明确喜欢的“粒子勾勒人物与城市”应出现在真实可操控的样镜中，不能最后只剩一个与内容无关的粒子背景。

### 三套组合的比较记录

用户已选定哈利波特感觉的书与童话般惊喜。A 因而成为当前主方向；B/C 继续作为书中段落的表现候选及完整形式比较，不再要求用户从头重复决定是否用书。

#### A · 哈利波特式记忆古书（当前主方向）

- 主载体：**哈利波特式魔法古书**与显影地图。星铁只借记忆组织，不改成星盘封面或科幻界面。
- 旅程：第二章以连续沙画展开她的五站与他的四站，在深圳汇合；第三章独立展示真实照片与信，第四章集中融合两部原版动画，第五章为精美蛋糕。
- 落幕：《狮子王》的星空接深蓝金色魔法蛋糕与许愿；最终蛋糕留在主画面，古书在旁。
- 小狗：彩绘二维，负责带信、跟随、陪读和结尾回应。
- 优势：最容易把哈利波特、《如我所书》的记忆组织方式、两部动画与真实人生内容组织成一个整体。
- 控制：主题借鉴有主次；不堆霍格沃茨校徽、游戏 UI、草原动物和城市地标做联名拼贴。

#### B · 风与星的沙画长卷

- 主载体：一张从头到尾不断变形的沙画光台。
- 路线：城市与人物轮廓连续变化，《小马王》的动势过渡到《狮子王》的稳定地平线。
- 互动：一笔一笔揭示、触摸停留、打开书信、点亮星空。
- 优势：最统一、最有舞台演出感；转场本身就是作品。
- 取舍：原版的彩色画面需要短暂完整显现，不能全被沙化；小狗若仍是彩绘，需要在书页边缘或休息段出场，避免漂浮贴纸感。

#### C · 可触摸的纸剧场

- 主载体：精绘纸机关、可拉动折页和层景。
- 路线：五个场景从同一张长纸展开，原版电影画面保留在纸窗/灯影里。
- 互动：拨动、拉开、轻触；小狗也像真正生活在纸页上。
- 优势：更俏皮、可爱、礼物感强；不依赖真实肖像和复杂 3D。
- 取舍：不宜让每一幕都像儿童教具，字体、用色和留白要克制。

建议先用 A 做结构，借 B 做代表旅程样镜。C 是有明显差异的备选方向。照片显影成为第三章独立体验，先用4–5张网图形成完整预览，之后可换本人照片；星图用于第四章收束并引出第五章深蓝金色蛋糕。五章顺序已确认，具体表达方法仍为制作提案。

**与第四章的连接：**星空中的一颗暖金星点先轻亮，再沿弧线落向下一幅图中蜡烛的位置；周围星点收成蛋糕表面的金色纹样，桌面逐渐显现。结尾回到现实礼物的质感。建议1.5–2秒，完成态必须提前准备，减少动态直接显示完整蛋糕。

**分层清单：**背景/桌面、盘子和接触阴影、无火蛋糕、金色细节、每根蜡烛与火焰、局部暖光、细烟、狗、可读祝福。书与蛋糕无需再建高精度实时3D；若未来使用Blender仅辅助纸张/构图，最终仍以效果决定是否保留。

### 五章之间的转场

| 转场 | 前一画面怎样生长成后一画面 | 触发与稳定落点 |
| --- | --- | --- |
| 一→二 | 书封金色墨迹流进纸页，拉成人生路线 | 开书后进入双路线地图；人物归属清楚 |

照片的显影和电影的开窗是不同事件，不能用同一个全屏淡黑糊弄。前后主形状、方向、光点和声音有对应关系；减少动态直接进入各章完整画面。

## 5 · 浪漫与童话惊喜

### 已确认的情绪主调：童话般的惊喜

**U：用户已选择“为你准备一场特别的奇遇”。** 浪漫的重心不再只是缓慢回顾和安静阅读，而是“触摸后世界回应”。安静的陪伴和被认真看见仍作为内层情绪，不能把礼物做成履历展示或电影素材展览。

#### 惊喜的节奏

每段只安排一个最主要的惊喜；发生后给她时间看清。先建立普通物件，再让它出现意料之外但能理解的变化。

> 亲爱的师宝宝：
>

>
> 师宝宝，生日快乐。谢谢你出现在我的故事里。书里还留着一些空白，往后的日子，想和你一页一页地写。

## 6 · 魔法古书与视觉构图

### 视觉总规则（P，样镜验证）

#### 构图与色彩

- 主视觉永远只有一个焦点；文字和小狗不同时争夺同一位置。
- 书的主色：纸白 `#F3E7CE`、墨褐 `#48352E`；夜空 `#18253B`；暖金 `#D6AF67`。这些是初始色板，不是从星铁或电影采样得到的官方色值。
- 沙画采用透光的暖色底与深沙层，留出真正的亮部；不靠全屏发光点和强模糊。
- 原版电影保留其主体颜色与表情，仅用周围纸张、光源和构图连接，不叠重滤镜毁掉原画。
- 默认轻微或无胶片颗粒。正文、真实照片与触摸提示不参与沙粒噪声。
- 页面上不展示帧率、渲染器名、素材版本等技术信息。

#### 桌面与手机分别构图

| 项目 | 设计初值 | 验证重点 |
| --- | --- | --- |
| 桌面视觉母版 | 2400×1600 分层绘画 | 书本与场景有留白，不把正文铺满屏宽 |
| 手机视觉母版 | 1440×2560，独立安排主体 | 不把桌面横图直接中央裁切；原版双角色同框不能裁掉一人 |
| 正文 | 17–18 CSS px，行高约1.8 | 文字放大可读、信件连续滚动 |
| 触摸控件 | 命中区域约44×44 CSS px起 | 图标可小，手指仍能点到；与系统边缘手势留距离 |
| 手机书本 | 单页或竖向折页为主 | 不能把横向双页缩成两个无法阅读的小块 |
| 狗的画面占比 | 首次登场约画高的18%–24%，读信时更小 | 先看得清造型，随后不遮文字；实际由画稿调整 |

保留现有中文字体资产与系统回退；新字体只有确实改善效果才引入。正文在 DOM 中排版，不烘焙进图像；地点与学校名称必须准确、可复制。

### 哈利波特式记忆古书（外观方向U；具体制作P/V）

用户最终明确：书的样子与气氛必须是哈利波特。采用古旧装帧、烫金纹样、羊皮纸、封蜡和烛光。《如我所书》只参考故事被保存和回看的组织，不做中央星盘封面、悬浮科幻菜单或奖励界面。

#### 可制作的部件

1. 封面：深褐/墨绿古旧装帧候选，克制的金色纹样、边角磨痕、实体书脊；起初名字区域留白，触摸唤醒后显出“师宝宝”，随后进入记忆。颜色/纹样与显影细节为P，哈利波特外观和“只认识她”的整体故事已确认。
2. 书脊：翻页时是稳定的转轴；不能像整块 UI 卡片绕中心旋转。
3. 纸页：正反面、边缘阴影和翻起的局部亮面分开；手指拖动有可见进度。
4. 地图折页：她的五站与你的四站分别有归属，深圳汇合；地点为文字，路线为示意，不能混入未确认年份。
5. 记忆页：每页完成后保留一幅可回看的构图，非每次进入都重播长开场。
6. 书签：提供清楚但克制的返回/章节入口；点击不触发转场重复播放。
7. 信件：从书里展开到舒适阅读宽度，而不是把长信塞在缩小的书页里。
8. 封底/空白页：结尾保留未来延伸的空间；文案为祝福，不预言具体人生事件。

#### 翻页语义

- 点击下一页始终可用；拖拽页角是增强操作。
- 拖拽只在页角/边缘热点启动，正文区域仍可正常滚动和选字。
- 松手低于阈值回到原页，高于阈值落到新页；不能出现书页半开但界面已换章。
- 主体转场建议0.7–1.1秒，纸角触摸反馈立即出现。这是本项目初值，不是原作时长。
- 快速重复输入只保留一个明确的目标页，不累积十次翻页。
- 书内画面放大成为全屏场景后，保留一个可发现的“回到书页”入口。
- 返回地图时回到上次站点，不重新关闭整本书；重播整段由独立操作触发。

#### 要从星铁核实的视觉点

参考身份已确认，封面和目录两张玩家静帧已查看；记录见本文「参考研究与已观察证据」中的《如我所书》记录。尚需观察完整翻页时内容遮挡、阅读停留与退出方式。星铁封面已看见但不采用，其科幻色彩不替换哈利波特外观。尚无动态实看证据的地方只写本项目方案，不称“照原版复现”。

## 8 · 输入、状态与转场契约

### 输入与状态细则（P）

#### 一套操作语义

主操作是清楚的“继续/打开/返回”；轻扫、按住、拖拽为增强。必须让从未玩过网页互动的人不学习也能读完。

| 输入 | 行为 | 边界 |
| --- | --- | --- |
| 点击继续 | 推进一个故事段 `advanceBeat` | 当前推进中不累积多个请求；完成后按钮恢复 |
| 舞台轻扫 | 在允许的沙画段揭示一笔 | 建议18 CSS px意图阈值；先识别水平/指定方向，纵向阅读优先 |
| 按住 | 推进当前短笔触 | 不要求持续按完整章；松手建议0.25–0.45秒收完当前短笔触，保住可读画面 |
| 点击地点 | 进入该站或打开资料 | 不重置其他已看地点，回来仍在该站 |
| 摸狗 | 触发pet，主动回应 | 不推进旅程、不触发照片打开；多指只保留一个摸狗主体输入 |
| 滚动信 | 普通文档滚动 | 舞台不捕获该区域pointer，狗不在文字上方活动 |
| 返回 | 到最近稳定状态 | 不倒放长转场；从信返回第三章相册原页，从城市返回对应地图点 |
| 跳过镜头 | 落在分镜规定的完成态 | 停止该镜头的声音和粒子，不跳过全部私人文字 |

#### 公共状态

`ready → revealing → resting → transitioning` 与 `reading` 为互斥主状态；宠物有独立状态但服从阅读/后台暂停。

- `pointercancel`、`lostpointercapture`、失焦、换章都释放输入所有权。
- 页面进入后台暂停动态与声音；返回时停在合理状态，不补播整段离开时间。
- 快速后退/选章中止旧转场，只有新的章节可以提交最终状态。
- 加载下一幕失败时保持当前完整画面，提供重试或继续阅读；不能把用户困在黑屏。
- 减少动态效果保留相同文字、地点和事件，以完成态插画和短淡变替代大幅运动。
- 摄像头不开启也可完成所有核心互动；不为新增手势依赖重建权限流程。

## 9 · 二维小狗造型与动画

### 二维小狗：先换造型，再做好动作

用户已认可书与小狗的性格：书安静温柔，小狗带来调皮与惊喜；两只狗保留杏色活泼、奶油色安静的分工。造型仍需精绘定妆，不能因性格被确认就把旧模型视为合格。名字、现实犬种与对应真实宠物关系没有新资料时不添加私人设定。

**造型交付先于动画批量制作：**同一角色的正侧/四分之三视图，清楚的卷毛团块、耳朵轮廓、鼻口和脚掌，至少安静、好奇、开心三种表情。目标是像精心画出的动画角色，不是球体拼起来、现有 3D 截图描边，也不是通用圆眼贴纸。

| 动作组 | 必须看见的变化 |
| --- | --- |
| 待机 | 呼吸有小幅身体起伏，眨眼有间隔；两只狗不同时复制同一循环 |
| 注意/歪头 | 先眼神、后头、再耳朵轻跟随；保持鼻口体积 |
| 走近 | 脚有接地节奏、身体有轻微重心起伏；不是整张图平移 |
| 摸摸 | 头主动迎向触点，眼睛放松，耳朵和尾巴回应；不会突然切到无关动作 |
| 趴下/陪伴 | 有屈腿和收身体的过渡，安静停留；读信时降低活动 |
| 小庆祝 | 一次有预备动作的小跳或扑近，随后落地收势；不过度循环 |

主要表情和动作使用手绘关键姿态与必要中间帧；耳朵/尾巴可做有限分层变形。不能靠整体拉伸一张 PNG 假装完整动画。先做一只狗“注意 → 走近 → 被摸 → 趴下”的 6–10 秒短表演，造型和动作成立后再扩展第二只。

网页使用可控图集/分层动画，触摸能立即改变状态，松手有自然过渡。它们会带信、追随路线、趴在信边；不是固定角落不停播放 GIF 的挂件。摸狗命中区不覆盖书信滚动和按钮。

### 二维小狗详细交付（P/V）

#### 定妆

角色母版需含：色板、正侧/四分之三轮廓、眼睛开闭、耳朵位置、口鼻比例、毛团节奏、脚掌形状、开心/安静/好奇表情。暂不强加项圈、饰物和名字，避免版本间凭空变化。

两只必须为泰迪（贵宾犬的泰迪造型），正常四足，卷毛、垂耳、圆润口鼻，毛色杏/奶油。若后续选用现成可用二维犬素材，其轮廓与全部动作要来自同一角色系列；不拼五个作者的狗。

#### 动作状态表

建议以12帧/秒的手绘节奏起步，屏幕合成与触摸反馈独立更新。实际帧数按动作画稿决定，不把12fps当成画质保证。

| 状态 | 建议时长/循环 | 进入 | 退出与可中断点 | 必需画面 |
| --- | --- | --- | --- | --- |
| idle | 2–4秒，局部呼吸循环 | 出场收势结束/互动后 | notice或rest | 身体稳定、眨眼不机械同步 |
| notice | 0.5–0.8秒，一次 | 手指靠近/点击 | approach或idle | 眼先动，头稍后，耳再跟随 |
| approach | 1–1.5秒，一次短走近 | 有空间接近触点 | 落脚后pet/idle；换章可settle | 脚底锚点、重心起伏、尾巴跟随 |
| pet | 0.8–1.2秒可循环 | 触摸头/背允许区域 | 松手收势后idle/rest | 迎向手、放松眼、耳尾回应，不全身拉伸 |
| settle | 1–1.5秒，一次 | 读信/需要安静/庆祝结束 | rest | 前后腿屈曲有顺序，身体落地 |
| rest | 稳定，偶尔局部动作 | settle后 | 主动摸狗才唤醒；阅读不自主乱跑 | 胸口轻起伏、安静眼神 |
| celebrate | 0.8–1.2秒，一次 | 蜡烛熄灭事件 | 落地后settle/idle | 蓄力、跃起、落地和余动 |

动作的尾帧能接下一个动作首帧。图集提供起跳/落地/脚步等事件元数据，音效不能只按固定计时器猜。每只狗有自己的响应间隔，避免两个完全同步复制。

#### 输出内容

- 可编辑分层母版与动画工程。
- 透明运行图集、帧名、帧矩形、时长、pivot、脚底锚点、头/背触摸区、阴影层。
- 静态poster和减少动态版本。
- 单张图集建议控制在2048×2048以内，按动作组分页，具体看质量与解码预算。
- 一个2048×2048的RGBA解码纹理约16MiB；磁盘WebP小并不代表显存小。避免两只狗所有动作同时解码常驻。
- 对照检查：毛色、耳朵、鼻口、脚数、体积保持一致；透明边缘无脏色；走近没有脚滑，读信不盖字。

### 资产契约

继续使用以下已有入口，不为换美术形式另起一套下载器：

下一版建议命名 `memory-book-review-YYYYMMDD-vN`，实际制作时按日期分配；本文件出现该格式不表示 release 已存在。

建议逻辑分组（待实现，按现有 schema 映射，不擅自发明不兼容类型）：

| 分组 | 内容 | 加载时机 |
| --- | --- | --- |
| `book.*` | 封面、纸纹、地图、翻页局部遮罩 | 开场需要的部分先加载，其余按需 |
| `journey.<owner>.<station>.*` | 两人各站底稿、沙粒密度/轮廓、近远景层 | 当前站及必要的下一站 |

制作源文件与运行资源分开：`.kra`、动画工程、未压缩序列和参考截图留制作目录；网页只收到实际使用的压缩文件、图集及描述。参考作品和真实个人素材不因被下载就自动进入公开构建。

### 原版影像与本站的接口

原版画面优先。对每个候选先决定其形态：网页内允许的官方播放器，还是来源及使用范围明确的本地素材。二者不能混淆。

- 原版画面不能假定有透明背景或独立角色动画；网页交互负责显影、选择、停留与场景连接。
- 官方外部播放器可能有自己的控制、地区和网络条件。未实测前不承诺它可被全局静音精确控制、可任意 seek、可无缝裁剪或可当纹理。
- 若有独立播放器声音，必须接入可用的官方控制 API 或在明确无声模式中使用；做不到时提供主动观看入口，不出现全站已静音但影片发声。
- 主线地图、信与生日落幕不因外部播放器失败而消失。就地显示该段静态阅读状态，标明可重试；不得把失败外链伪装成已完成动画。
- 不抓取整部电影，不绕过 DRM，不以官方可免费观看的事实冒充再分发文件的许可。

### 候选发布顺序

1. 完成统一关键帧与一段有实际交互的代表样镜，确认它达到了当前创意目的。若只是规划，不上传空壳。
2. 准备新 release 的运行资源；先做一次来源、路径和必需格式检查。
3. 以新 ID 生成 manifest。已有 immutable 对象绝不覆盖，旧候选不改名冒充新版。
4. 网关加入新清单并保留生产与回退读取；上传新对象，最后写 ready。
5. 仅对本次新增/改动的上传对象做一次必要完整性校验，复用清单已有摘要；未改资源不重新下载算SHA，不反复全桶扫描。具体失败只重试受影响对象。
6. 构建候选网页，确认 `/birthday-card/` 路径、当前输入、关键转场和静音；保留失败可阅读入口。
7. 以可审阅结果决定是否替换生产。没有真实画面验收记录，不把“CI 通过”写成“美术通过”。
