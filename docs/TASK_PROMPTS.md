# birthday-card 任务提示词

按 [OpenAI 关于技能与提示词的建议](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 编写：常驻约定保持简短，专项资料按需读取，任务写清目标、边界和完成条件。以下是发起任务时选用的模板，不是每轮都要执行的流程。

仓库约定在 [AGENTS.md](../AGENTS.md)。视觉技能位于 [SKILL.md](../.agents/skills/birthday-visual-review/SKILL.md)，可在支持仓库技能发现的 Codex 环境中使用 `$birthday-visual-review`；其他环境可让助手直接读取该文件。

方括号内容由发起者替换。每次只选择适合当前任务的一段。

## 视觉改进

```text
请基于 birthday-card 当前代码，使用 $birthday-visual-review 改进 [具体场景/角色]。

当前问题：[可观察的问题；有截图或录屏就附上]。
目标效果：[希望看到的变化，以及需要保留的特征]。
本次范围：[相关场景或模块]。

请完成实现，并在工具可用时运行页面、观察关键动作和桌面/手机布局，修复本次发现的问题。
完成标准：[本轮可观察的验收条件]。
满足这些条件后结束，只报告改动、验证结果和未验证项。
```

例如改进泰迪时，可把目标写为“耳朵和视线对摸摸有连贯反应，待机与开心动作切换自然，手机上不遮挡翻页按钮”，比只写“更生动”更容易验收。

## 问题修复

```text
请修复 birthday-card 的 [具体问题]。
复现方式：[进入哪个章节、执行什么操作、浏览器或设备]。
实际结果：[当前表现]。
预期结果：[正确表现]。

只修改解决该问题所需的部分，保留现有交互。
完成标准：复现路径恢复正常，并针对原因做必要验证；涉及画面或音频时实际观察对应行为。
若已有测试可覆盖就复用，仅在需要防止该问题复发时补充测试；结论充分后结束。
```

## 功能增量

```text
请为 birthday-card 增加 [具体能力]。
使用场景：[谁在什么章节执行什么操作]。
输入与结果：[使用哪些已有内容，用户会看到或听到什么]。
约束：[需要保留的交互、性能或内容要求]。
完成标准：[正常路径及与本功能有关的降级行为]。

请从实现推进到必要验证，并修复本次引入的问题。
如果有多种合理实现，可自行选择符合现有结构的方案；缺少真实个人资料时沿用现有示意内容并说明。
```

## 明确交付范围

在选用的模板末尾补充适合本次任务的一句：

- 只准备改动：`完成实现和必要验证，保留改动供我查看，不推送。`
- 提交到指定分支：`完成后 commit 并 push 到 [目标分支]；不要强推或覆盖他人改动。`

当前推送 `main` 会触发 GitHub Pages 部署；如只想审阅，可指定工作分支。已有明确交付授权时不必重复确认。
